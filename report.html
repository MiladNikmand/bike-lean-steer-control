Bike Lean-Steer Control

Whipple–Carvallo Benchmark Model  ·  Linearized lean-steer dynamics  ·  Multiple feedback controllers  ·  Disturbance analysis

1   Physical model

The bicycle is modelled as four rigid bodies — rear frame + rider, fork + handlebar, rear wheel, front wheel — constrained to roll and steer about a single upright equilibrium. The two generalised coordinates are the roll angle \(\phi\) and the steer angle \(\delta\). Linearising about straight-ahead upright motion at constant forward speed \(v\) gives the canonical Whipple–Carvallo equations:

\[ \mathbf{M}\,\ddot{q} \;+\; v\,\mathbf{C}_1\,\dot{q} \;+\; \bigl(g\,\mathbf{K}_0 + v^2\,\mathbf{K}_2\bigr)\,q \;=\; \mathbf{F} \]

\(q = [\phi,\,\delta]^\top\)  |  \(\mathbf{M}\) mass matrix  |  \(\mathbf{C}_1\) gyroscopic/damping  |  \(\mathbf{K}_0\) gravity stiffness  |  \(\mathbf{K}_2\) speed-squared stiffness

Converting to first-order state-space form with state \(x = [\phi,\,\delta,\,\dot\phi,\,\dot\delta]^\top\):

\[ \dot{x} = A(v)\,x + B\,u, \qquad A = \begin{bmatrix} \mathbf{0} & \mathbf{I} \\ -\mathbf{M}^{-1}(g\mathbf{K}_0+v^2\mathbf{K}_2) & -v\,\mathbf{M}^{-1}\mathbf{C}_1 \end{bmatrix},\quad B = \begin{bmatrix}\mathbf{0}\\\mathbf{M}^{-1}\end{bmatrix} \]

2   Stability regimes

The open-loop eigenvalues of \(A(v)\) determine passive stability. There are three distinct regimes:

  • Low speed (\(v \lesssim 4.3\) m/s) — unstable: both the weave (oscillatory lean + steer) and capsize (slow lean) modes have positive real parts.
  • Self-stable band (~4.3–6 m/s) — gyroscopic and caster effects naturally stabilise all modes with zero rider input.
  • High speed (\(v \gtrsim 6\) m/s) — capsize mode returns: a single real eigenvalue creeps positive. The weave mode remains stable but the bike drifts sideways without correction.

All controllers output a steer torque \(T_\delta\) to the front assembly.

4   Physical constraints

  • Roll hard stop \(|\phi| > \phi_\text{lim}\) — bike has fallen over; the linearised model is invalid. Simulation terminates and the run is marked FAILED.
  • Steer saturation \(|\delta| > \delta_\text{sat}\) — handlebar at its mechanical stop. Steer is clamped and the simulation continues. Saturation events are logged.
  • Slew rate \(|\dot\delta| > \dot\delta_\text{max}\) — actuator speed limit. Each integration step enforces this before the position saturation clamp.

6   How to update this report

  1. Run a new analysis: bike_launch or run_all
  2. Regenerate the data bundle: bc_build_report
  3. Reload this page — the Results section below updates automatically.

Keep report.html and report_data.js in the project root folder. On GitHub Pages the page renders live at the linked URL above. Viewing locally over file:// also works because the data is bundled as a JS variable, not fetched via XHR.
